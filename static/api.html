REST API

Everything the web UI and the tsig CLI do goes through these endpoints. All bodies are JSON. Errors come back as {"error": "..."}. Scalars, points and signatures are little-endian hex (points 40 bytes, signatures 80 bytes: s ‖ e). Mutating calls (join / dkg / commit / partial) are authenticated: join carries a MetaMask personal_sign over the join statement, and the rest carry a sig field — an ECgFp5 Schnorr signature over the canonical request payload, verified against the auth pubkey registered at join.

POST/api/rooms

Create a room with a t-of-n policy. Optionally pass addresses — an allowlist of exactly n ETH addresses: only they can join, and the roster is bound into every participant's signed join statement. Returns the five-word room code. 

curl -X POST /api/rooms -d '{"threshold": 3, "total": 4, "addresses": ["0xabc...", ...]}'
→ {"room": "apple-carrot-thumbs-fjord-cedar", "threshold": 3, "total": 4, "allowed": [...]}
GET/api/rooms

List every room with participant / proposal counts and DKG status.

curl /api/rooms
→ {"rooms": [{"room": "...", "threshold": 3, "total": 4, "joined": 4, "proposals": 2, "groupPk": "..."}]}
GET/api/rooms/{room}

Full room state: participants (address, auth/enc pubkeys, join signature, DKG commitments, proof-of-knowledge), all DKG share ciphertexts ("from-to" → ECIES blob, only decryptable by the recipient), the group public key, and all proposals with their request nonce, FROST nonce commitment pairs, partial signatures, final signature and validity. 

curl /api/rooms/apple-carrot-thumbs-fjord-cedar
POST/api/rooms/{room}/join

Join with an ETH address, per-room ECgFp5 auth + encryption pubkeys, and a MetaMask personal_sign signature over the canonical join statement binding them all, including the room's t-of-n policy and (if set) the address allowlist roster. The server verifies by ecrecover and rejects unlisted addresses; every client re-verifies. Rejoining returns the same index. 

curl -X POST /api/rooms/{room}/join -d '{"address": "0xabc...", "authPk": "...", "encPk": "...", "ethSig": "0x..."}'
→ {"idx": 2}
POST/api/rooms/{room}/dkg

Post your DKG round: t polynomial commitments (A_k = a_k·G), a Schnorr proof-of-knowledge of a_0 (rogue-key protection, verified server-side), and a share f(j) for every participant j encrypted to their encryption pubkey. Recipients decrypt and verify their own shares; once all n rounds are in, the group public key Σ A_0 is derived (and recomputed client-side). 

curl -X POST /api/rooms/{room}/dkg -d '{"idx": 1, "commitments": ["..."], "pok": {"r": "...", "mu": "..."}, "shares": {"1": "<ciphertext>", ...}, "sig": "..."}'
POST/api/rooms/{room}/proposals

Propose a 40-byte Lighter transaction hash to sign (hex, 0x optional); the room signs the hash directly, so the aggregate signature is a valid L2 signature for the transaction. Requires the DKG to be finished. nonce is a client-chosen random value (16+ characters) that makes the signed request unique, so a captured request replayed against the server returns the original proposal instead of creating a duplicate. The request must be signed with the proposer's auth key over propose/{room}/{proposer}/{message}/{nonce}; the server verifies it, enforces uniqueness on (room, proposer, nonce), and clients re-verify attribution locally.

curl -X POST /api/rooms/{room}/proposals -d '{"message": "0x1234...abcd", "proposer": 1, "nonce": "<random, 16+ chars>", "sig": "..."}'
→ {"id": 7}
→ {"id": 7, "replayed": true}   # same (room, proposer, nonce) submitted again
POST/api/proposals/{id}/commit

Post your FROST nonce commitment pair: hiding D_j = d_j·G and binding E_j = e_j·G. When t commitments are in, the signer set locks (first t committers by index). 

curl -X POST /api/proposals/{id}/commit -d '{"idx": 1, "d": "<40-byte hex>", "e": "<40-byte hex>", "sig": "..."}'
POST/api/proposals/{id}/partial

Post your FROST partial signature z_j = d_j + ρ_j·e_j − c·λ_j·x_j (ρ_j is the binding factor over message + signer set + all commitments). The server verifies it against your public share before accepting. Only locked signers may post. 

curl -X POST /api/proposals/{id}/partial -d '{"idx": 1, "s": "<40-byte hex>", "sig": "..."}'
POST/api/proposals/{id}/execute

Aggregate z = Σ z_j into the final 80-byte Schnorr signature (z, c) and verify it against the group public key with the SDK's schnorr.Validate. Stores and returns the result. 

curl -X POST /api/proposals/{id}/execute -d '{}'
→ {"sig": "<80-byte hex>", "valid": true}

CLI

Prefer a terminal? go build ./cmd/tsig from the repo, drop a .env with TSIG_SERVER and TSIG_SEED, then: tsig create · list · join · status · dkg · propose · sign · execute · watch.
